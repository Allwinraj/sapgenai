Five specialist skills  ·  the only things that ever touch the data

Each one is a boiler plate: a versioned behaviour file, a config schema, modes, and named exit ports.
Skill anatomy Same shape every time, so a new skill drops in without engine changes.
Behaviour version YAML, listable per skill
Config from schema panel generated, not coded
Mode switches the strategy inside
Named exit ports routing declared, not scripted

MathPlain-language formula compiled to a checked expression, then applied out: default

Read it as a sentence: work arrives at a touchpoint (1), the orchestration understands it and assembles a flow (2), five specialist skills execute that flow and hand a typed envelope to each other (3), a skill may reach a writer, a mailbox or a business system but only after a person clicks (4). The workbench builds and packages the flow (5), the context fabric supplies the evidence (6), assurance records what happened and feeds the next version (7), identity and policy are the missing wrapper (8), and it all sits on a plain runtime (9).
